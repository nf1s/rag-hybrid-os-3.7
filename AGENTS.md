# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Overview

A Retrieval-Augmented Generation (RAG) system on top of **OpenSearch 3.7** hybrid search (semantic + full-text). A **Pydantic AI** agent (FastAPI service) uses `opensearch-py` directly via a `@agent.tool_plain` function — no MCP server is involved. Answers are generated by a **llama-cpp-python** server running as a background process in the same container (no external LLM dependency).

The app is deployed to Kubernetes via **Skaffold + Helm**. Four components run in the `opensearch` namespace as init Jobs (`template-job`, `model-job`, `seed-job`) plus the long-running `rag-api` Deployment and an Nginx `ui` serving the chat frontend.

## Repository Layout

```
api/                  # Python RAG API (FastAPI + Pydantic AI agent)
  app/main.py         # FastAPI app, agent, chat/query/stream endpoints
  app/models.py       # Pydantic request/response models (ChatRequest, ChatResponse, Source, ...)
  app/settings.py     # Env-driven settings (OPENSEARCH_URL, LLM_URL, LLM_MODEL)
  start.sh            # Starts llama-cpp-python server (bg), then uvicorn
  requirements.txt
frontend/             # Nginx + single-file chat UI (index.html, vanilla JS)
template-job/         # Applies the `article` index template (basic text mapping)
model-job/            # Registers + deploys all-MiniLM-L12-v2, upgrades template to `semantic` field,
                      # creates chunking ingest pipeline + hybrid search pipeline
seed-job/             # Bulk-indexes 30 sample articles via the chunking pipeline
charts/
  hybrid-search/      # Parent chart: OpenSearch + Dashboards (deps in charts/)
  ui/, rag-api/, template-job/, model-job/, seed-job/   # component charts
skaffold.yaml         # Build (5 images) + deploy (6 Helm releases — no MCP server image)
justfile              # Task runner shortcuts (deploy, logs, port-forward, rebuild, ...)
```

## Tech Stack

- **Backend:** Python 3.12, FastAPI, Pydantic AI (`pydantic-ai`), `opensearch-py`
- **LLM:** llama-cpp-python (in-container server, GGUF model, OpenAI-compatible `/v1` endpoint)
- **Search:** OpenSearch 3.7 — `semantic` field type, `neural` + `multi_match` hybrid query, `hybrid-search-pipeline` (z_score normalization + arithmetic_mean combination, weights `[0.59, 0.41]`), `text_chunking` ingest pipeline (100-token, 15% overlap)
- **Frontend:** Vanilla HTML/CSS/JS, served by Nginx; markdown rendered client-side
- **Infra:** Kubernetes, Skaffold, Helm, `just` task runner

## Common Commands

Run from the repo root. The `justfile` is the source of truth for shortcuts.

### Deploy / teardown
```sh
just deploy        # skaffold run — build images, deploy all 6 Helm releases, run init Jobs
just delete        # skaffold delete
just render        # skaffold render (dry-run, print manifests)
just rebuild       # wipe + re-download Helm chart deps (opensearch, dashboards)
```

### Inspect running system
```sh
just ps            # kubectl get pods -n opensearch
just svc           # kubectl get svc -n opensearch
just logs          # OpenSearch logs
just rag-logs      # RAG API logs (follow)
just model-logs    # model-job logs
just seed-logs     # seed-job logs
just template-logs
```

### Port-forwards
```sh
just port-forward-ui      # UI at http://localhost:8080
just port-forward-rag     # RAG API at http://localhost:8000
just port-forward         # OpenSearch API at :9200
just port-forward-dashboards   # :5601
```

### Restart / reseed
```sh
just rag-restart     # kubectl rollout restart deployment/rag-api
just reseed          # delete seed-job then skaffold run (re-seeds data)
```

### Probe APIs
```sh
just curl-rag        # GET /api/rag/health
just curl            # GET OpenSearch root
curl -s http://localhost:8000/api/rag/chat/stream -H 'Content-Type: application/json' \
  -d '{"message": "What is quantum computing?"}'
```

## Testing / Linting

There is **no automated test suite** in this repository. There are no `pytest`, `ruff`, `mypy`, or lint configurations to run.

When validating changes:
- For Python (`api/`): smoke-test by deploying and hitting `/api/rag/health` and `/api/rag/chat`.
- For shell jobs: inspect `kubectl logs` of the relevant Job.
- For Helm charts: use `just render` (or `skaffold render`) to verify manifests.
- For the frontend: port-forward the UI and exercise the chat manually.

If you introduce tests or linting, add the exact commands here and to the `justfile`.

## Environment & Configuration

The RAG API reads three env vars (see `api/app/settings.py` and `charts/rag-api/values.yaml`):

| Variable | Default | Notes |
|----------|---------|-------|
| `OPENSEARCH_URL` | `http://hybrid-search-single:9200` | in-cluster OpenSearch service |
| `LLM_URL` | `http://127.0.0.1:8001/v1` | llama-cpp-python server in same container |
| `LLM_MODEL` | `qwen2.5-1.5b-instruct` | model name sent to the inference server |

Override via `charts/rag-api/values.yaml` and redeploy with `just rag-restart` (or `just deploy`).

## Architecture Notes (important for code changes)

- **Search before model (no tool calling):** Small LLMs (<3B params) don't reliably support function/tool calling. Instead, the chat/query endpoints call `search_hybrid()` from `api/app/search.py` **before** invoking the model, injecting results directly into the prompt as context. This is done in `_search_and_format()` in `api/app/main.py`. If you change index mappings or query structure, keep the search params and pipeline in sync.
- **System prompt expects context in the message:** `SYSTEM_PROMPT` in `api/app/main.py` tells the model to answer based on context provided in the user's message (prepended as "Retrieved articles:\n..."). The hybrid query is built in `search.py` — keep the (neural + multi_match) structure and pipeline params in sync.
- **Hybrid scoring:** `model-job` creates `hybrid-search-pipeline` with `z_score` normalization and `arithmetic_mean` combination, weights `[0.59, 0.41]`. The agent does NOT specify the pipeline per-request; it's passed as a search param in `search.py`. Keep weights and normalization in sync between `model-job/entrypoint.sh`, `api/app/search.py`, and any docs.
- **Index lifecycle:** `template-job` creates a basic `article` template; `model-job` overwrites it with the `semantic` field mapping (requires the deployed model's `model_id`). `model-job` deletes the `article` index only if it registered the model fresh, so redeploys are idempotent and don't wipe data.
- **Seed idempotency:** `seed-job` checks `_count` and skips if the `article` index already has documents. To force a reseed, `just reseed` (deletes the Job so it reruns; existing docs are NOT deleted — clear the index first if needed).
- **Frontend proxy:** `frontend/nginx.conf` proxies `/api/rag/` → `http://rag-api.opensearch.svc.cluster.local:8000` (FQDN required; short names fail). If you change the service name/namespace, update both `nginx.conf` and the Helm chart.
- **In-memory conversation store:** `_conversations` in `api/app/main.py:72` is a process-local dict — restarting the pod clears history. Don't rely on it for durability.

## Conventions

- **Commit style:** Conventional Commits, lowercase, scoped where helpful (e.g. `feat:`, `fix:`, `chore:`, `readme:`, `diagram:`). See `git log` for examples.
- **Shell jobs:** POSIX `sh` (`#!/bin/sh`), `set -e`, wait-for-dependency loops with `curl` + `sleep`. Alpine-based images with `curl` (+ `jq` where needed).
- **Python:** Python 3.12, `from __future__` not used (3.12+ syntax like `str | None` is fine). PEP-style; small focused modules. No comments unless explaining non-obvious logic.
- **Helm charts:** one chart per component under `charts/`; values in `values.yaml`; minimal templating. The `hybrid-search` parent chart only pins the OpenSearch/Dashboards upstream chart deps.
- **Security:** OpenSearch security is intentionally disabled (`plugins.security.disabled: true`). The `opensearch-py` client connects without auth. Do not add auth handling without coordinating across `model-job`, `template-job`, `seed-job`, and `rag-api`.
